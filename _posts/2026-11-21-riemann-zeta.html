On Friday night I asked Codex to submit a Lean file to the critical-line challenge on riemannzeta.fun and wait for the verdict. Its leaderboard ranks machine-checked lower bounds for the proportion of distinct zeros on the critical line. The record was about 67.36%. The number I wanted to submit was 669/800, or 83.625%. I gave it permission to keep working while I slept.

The site rejected the submission. Just above the backtrace, the log said Build completed successfully (8838 jobs). So what, exactly, had it checked?

Where 83.625% came from

Back in August, Levent Alpöge and Ralph Furman proved a bound on how many distinct zeros the Riemann zeta function has. Imagine a window containing four simple zeros and one double zero. You can point to five different locations, but the total count is six because the double zero counts twice. The fraction of distinct zeros in that example is 5/6.

Their theorem gives a lower bound slightly above 83.625% for distinct zeros anywhere in the critical strip as the height grows. The leaderboard counts only distinct zeros on the critical line, where the real part is ½. On November 20, Alpöge released a Lean proof of the Riemann hypothesis, which says that every nontrivial zero lies on that line. If I could use that theorem in the same Lean file, every distinct zero in the August result would count toward the leaderboard’s numerator. The August paper · Alpöge’s announcement

The missing argument

The submission log showed an argument called hRH : RiemannHypothesis. In Lean terms, I had a function waiting for an input. Give it a proof of RH and it returns the 83.625% bound. That explains the successful build. The leaderboard requires a theorem it can check without supplying the input.

The first error the site actually reported was more mundane. Its exporter looked for a declaration named candidate_strict_improvement and couldn’t find it. That part was easy to fix. The harder part was getting the published RH proof into the build. The site uses Lean 4.33.0-rc2 and accepts a single source file of up to 2 MB. The RH release uses Lean 4.33.1. Even the module we wanted to import pulled in about a gigabyte of Lean source. Leaderboard rules

At that point I wanted to know whether the whole argument would compile on my Mac. Codex rebuilt the zero-counting library against the exact version of Mathlib used by the RH release. The original counting proofs compiled there. That let us import Alpöge’s theorem and pass it to the counting lemma. The finished file supplies hRH here.

(Zeta23.RH_implies_all_on_line
  _root_.riemannHypothesis a b).2

The .2 picks out the equality we need. In the interval from a to b, the number of distinct zeros on the line equals the number of distinct zeros in the strip.

The finished file proves the bound from height T to 2T and from 0 to T. In either window, for any positive ε, the proportion is at least 669/800 − ε once T is sufficiently large. Both declarations passed Lean’s kernel replay. A second build from a fresh checkout produced the same axiom reports. For the RH dependency we used the published, hash-checked build artifacts. My verification log · Andrew Sutherland’s checks of the RH release

I started this for a leaderboard score and ended up with a file I can run on my Mac. The 83.625% bound already follows from the published math. My contribution here is getting the two developments to build together. If you have the RH checkout built, you can run verify.sh and check the result yourself.
